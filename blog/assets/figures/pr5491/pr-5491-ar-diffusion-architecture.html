1The big picture — one tick's journey

The stack splits at a process boundary: the control plane owns event ordering and commit semantics; the engine side owns worker-local session state, model execution, and paged KV. They talk over the standard Omni request path — the tick hides inside sampling_params.extra_args["ar_diffusion_tick"] — and comes back as a typed metadata envelope that the control plane must match exactly before committing anything.

Fig 1 — Layers and ownership. The engine seam is three touch points: registry entries, the worker delegation, and one engine-args propagation hunk. Everything stateful about sessions is worker-local; everything about ordering and commit lives client-side.

2One tick, end to end

The eight steps below are the PR's realtime request lifecycle, verified against the merged code. Steps 1–3 run client-side, 4–6 in the engine, 7–8 back client-side.

1

Accept interaction event

accept_event() validates monotonic event_id, dedups, rejects stale ids against the committed/in-flight floors, enforces queue backpressure. The event is queued only.

2

Build an immutable tick

next_chunk() snapshots pending events; the reducer's prepare() turns them into one block of camera controls without touching committed state. Output: ARDiffusionTickRequest with session / request / chunk / applied-event identities.

3

Enter the standard Omni path

execute_tick() asks the prompt provider for a normal prompt, hides the tick in extra_args, and calls AsyncOmni.generate(). Engine routing keeps its UUID suffix; tick.request_id stays the independent correlation id.

4

Bind worker-local AR state

DiffusionWorker.execute_model delegates to the AR runner, which parses the tick, finds or creates the session (LRU eviction at capacity), and binds its ARDiffusionKVState.

5

Generate one block

Pipeline validates continuity, builds conditioning, reuses paged self-attention history, runs 4 DMD steps (probe KV in scratch), and commits 3 clean latent frames during the final pass.

6

Return the typed envelope

DiffusionOutput(output={"payload": latents, "metadata": {"ar_diffusion": …}}). Realtime output is latent-only — no streaming VAE in this PR.

7

Validate + commit

Consumer validates the complete metadata snapshot, including the correlation request id. Only then does the session commit the reducer, remove applied events, and advance chunk_index.

8

Fail closed

Any worker, metadata, or commit failure marks the session FAILED, releases worker state, and rejects in-place retry — callers must explicitly reset or close.

3Fail-closed session state machine

A successful worker call alone never commits transport state; a failed one always tears down both sides. The only way back from FAILED is an explicit reset.

Fig 2 — Lifecycle transitions. Fail-closed is structural: the runner releases its side on any forward exception, and the second close from the session layer is idempotent.

4Paged KV residency — sink, window, current block

Each session keeps an attention sink (first 9 chunks), a recent window (18 chunks), and the in-flight block. Everything in between is pruned after each commit, so residency per session is bounded while the world stays consistent with the offline oracle's sink+tail policy.

Fig 3 — Geometry pinned by the model contract: sink 9 / block 3 / window 18. The offline direct path replays the same sink+tail window, which is why direct-vs-paged parity was bit-exact.
